# Contributing

Before editing, identify canonical scope and record type, search existing IDs, preserve source history, label the evidence/design status, and check rights and consent.

## Workflow
1. Define a bounded task and acceptance criteria.
2. Draft on a branch or pull request.
3. Add stable IDs, provenance, evidence status and rights status.
4. Validate records and update regression cases.
5. Request human review; community/specialist review is needed for high-impact claims about community language practices or standardization.
6. Record decisions, rationale and alternatives.
7. Release versioned changes and identify downstream impacts.

## Do not
- Present generated statements as sources.
- Infer etymology from resemblance alone.
- Label a proposal as attested.
- Copy third-party dictionaries/corpora without checking permissions.
- Flatten real-world variation for model convenience.
- Rewrite downstream applications automatically.
- Publish secrets, private data or non-consensual recordings.

## Definition of done
Acceptance criteria pass; provenance and rights are recorded; relevant tests are updated; review is complete; changelog/decision log is updated.
