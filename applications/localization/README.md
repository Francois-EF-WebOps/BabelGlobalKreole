# Programming and software localization application track

## Purpose

This track covers user-interface strings, terminology, developer documentation, error messages, help text and software-localization bundles. It consumes sourced framework records and preserves locale/variety distinctions.

## Record contract

Use `schemas/creative-work.schema.json` with `type: localization` for a curated localization work, or `type: code` for an authored code artifact. Declare the author, license, AI-use flags, language/variety/orthography, record IDs used, label, status and generation method. AI-assisted/generated content must name the tool and state whether its terms were verified.

## Rights and evidence

- Never treat a translated string as proof of attested usage without a source.
- Preserve source text, target text, context, software version, review status and a precise record/source trail in future localization exports.
- Do not copy proprietary string catalogs or documentation without permission.
- Owner-authored examples require owner-selected license and AI-use flags before publication.

## LLM use

Use only records whose rights permit the intended retrieval, training, speech or synthetic-data operation. Unknown rights block reuse. Validate output with human review and context-specific tests; a fluent translation is not necessarily correct for the target variety.

## Current evidence state

No localization bundle is published. This track defines boundaries and metadata requirements, not a functioning translation service.
