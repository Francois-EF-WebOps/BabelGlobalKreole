# Music application contract

Music is a first-class application, not the framework's defining boundary.

Inputs: language/variety or constructed-language scope; framework version and relevant record IDs; orthography/pronunciation policy; creative brief; rights/provenance for reference lyrics, samples, recordings and sources.

Pipeline: `BRIEF → SELECT RECORDS → DRAFT → LINGUISTIC CHECK → RIGHTS CHECK → HUMAN REVIEW → EXPORT → FEEDBACK`.

Separate linguistic constraints from genre/rhythm/performance instructions. A music-generation model is not a linguistic authority. Label poetic departures as creative choices, not validated usage.

Record brief version, actual model/tool used, date, language records referenced, human edits, rights notes, asset IDs and evaluation. Do not invent a provider API or claim automation before a reproducible integration test.
